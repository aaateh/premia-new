# Scroll Burn — локальная демонстрация

Проба эффекта **Scroll Burn** для «Суровой премии»: следующий экран «прожигает» предыдущий органической кромкой, пока вы скроллите. Работает в обе стороны, без видео, WebGL и сторонних библиотек.

Техника воспроизведена по демонстрации [Scroll Burn](https://www.framer.com/marketplace/components/scroll-burn-effect/) (Kush Verma, Framer Marketplace). Это самостоятельная реализация для оценки эффекта, а не копия платного компонента.

> **Промт и полная инструкция для ИИ по переносу на сайт:**
> [ПЕРЕНОС-НА-САЙТ.md](ПЕРЕНОС-НА-САЙТ.md). Там разметка, ядро CSS, подключение,
> выбор секций, подводные камни, чек-лист и порядок деплоя.

## Как посмотреть

Проект уже раздаётся единым dev-server (не нужно поднимать отдельный `http.server`):

```
http://127.0.0.1:8090/premiya/Эффекты/scroll-burn/
```

или

```
http://premiya.localhost:8090/Эффекты/scroll-burn/
```

Демо подключает шрифты из `fonts/` через `../../fonts/`, поэтому открывать его нужно именно по этому адресу, а не как `file://`.

## Что происходит

1. Внутри каждой секции лежит абсолютный слой `.burn` цвета **следующего** экрана.
2. В Chrome цветной слой `.burn__fill` внутри `.burn__pad` растягивается по `scaleY(progress)`, и к нему применён живой SVG-фильтр:
   - `feTurbulence` — органический шум;
   - `feDisplacementMap` — смещает край на «размер кляксы»;
   - `feGaussianBlur` — смягчает;
   - `feComponentTransfer` с `discrete`-таблицей — жёсткий порог альфы, дающий рваную кромку;
   - ещё один лёгкий блюр — чтобы край не был пиксельным.

   В Safari/WebKit 27 полноэкранный живой фильтр не отрисовывается, поэтому
   там кромка рисуется простым SVG-путём с CSS-заливкой внутри `.burn`
   (абсолютно, `inset: 0`): цвет — тот же CSS-цвет, что у следующей секции,
   низ уходит за границу блока, поэтому на стыке нет щели, а слой
   прокручивается вместе с секцией и не «плавает».
3. Кромка пересчитывается по мере роста заливки, поэтому меняется, как в оригинальном Framer-компоненте; при скролле вверх прожиг отступает.
4. Прогресс считается по положению секции относительно вьюпорта и сглаживается через `requestAnimationFrame` (инерция).
5. Параметры пульта сразу меняют фильтр и геометрию; направление «вниз» переворачивает заливку.
6. При `prefers-reduced-motion` прогресс применяется мгновенно, без инерции.

## Пульт

Кнопка **«Пульт»** справа снизу открывает параметры (не сохраняются между перезагрузками):

| Параметр | В Framer | Что делает |
|---|---|---|
| Направление | Grow | прожиг снизу вверх или сверху вниз |
| Сглаживание | Smoothing | 1 — мгновенно, 0.02 — лениво |
| Начало | Start | положение верха секции в % окна браузера, при котором прожиг = 0 |
| Конец | End | положение верха секции в % окна браузера, при котором прожиг = 1 |
| Размер кляксы | Blob Size | амплитуда смещения края, px |
| Шум X / Y | Noise X / Y | частота шума по осям |
| Детализация | Detail | число октав шума |
| Seed | Seed | зерно рисунка |

В Chrome выставлены **Start = 0, End = −100**: экран успевает полностью показаться, а прожиг идёт, пока он уезжает, примерно на один экран скролла. В оригинальном компоненте по умолчанию **Start = 100, End = 0** — этот режим тоже можно собрать ползунками.

В Safari/WebKit по умолчанию стоят настройки из компонента:
**Smoothing 0.32, Start −10, End −100, Blob Size 310 px, Noise X 0.008,
Noise Y 0.002, Detail 5, Seed 8**. Seed — базовый: каждый следующий блок
получает свой рисунок (`seed + index × 17`). Их видно в пульте при открытии
демо в Safari; сброс возвращает именно эти значения.

## Как встроить в другой блок

- Добавить в **уходящую** секцию `<div class="burn" data-burn data-color="#ЦВЕТ_СЛЕДУЮЩЕЙ_СЕКЦИИ"></div>`.
- Фон следующей секции должен быть плоским и совпадать с `data-color`, иначе на стыке будет виден шов.
- Для секции выше вьюпорта слой можно прижать к нижним 100vh, как в оригинале; здесь он растянут на всю секцию.
- В Chrome на каждый прожиг — свой живой SVG-фильтр, в Safari/WebKit — свой SVG-путь. Слой скрывается при прогрессе 0, чтобы не тратить ресурсы.

## Замечание по производительности

Это оригинальная техника: живой SVG-фильтр пересчитывается во время скролла. Обновление событийное: `requestAnimationFrame` запускается на скролл, resize или смену параметров; когда сглаживание догнало цель, цикл останавливается. В фоновой вкладке — пауза, постоянных таймеров нет. Живой фильтр тяжелее canvas-кэша, зато кромка ведёт себя как в Framer; проверяйте на целевом устройстве. В Chrome работает живой SVG-фильтр. В Safari/WebKit 27 полноэкранный живой фильтр не отрисовывается — для WebKit демо автоматически переключается на SVG-путь с CSS-заливкой: цвет берётся из следующего блока, настройки и прогресс сохраняются. Путь лежит внутри `.burn` и растянут на секцию, поэтому кромка закреплена за границей блока: нет плавающего слоя и щели на стыке.
