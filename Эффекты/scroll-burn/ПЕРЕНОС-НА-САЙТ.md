## 1. Что это за эффект

Следующий экран «прожигает» предыдущий органической кромкой, пока пользователь
скроллит. Кромка выглядит как край горящей бумаги или растекающихся чернил:
она неровная, с отдельными каплями и островками. Эффект работает в обе стороны:
вверх — огонь отступает.

В демонстрации шесть экранов и пять переходов:

1. тёмный `#080607` → бумага `#ECE9E3`;
2. бумага → тёмный;
3. тёмный → оранжевый `#F56624`;
4. оранжевый → тёмный;
5. тёмный → бумага.

Демо: `Эффекты/scroll-burn/index.html`. Локально открывается через общий
dev-server проекта:

```
http://127.0.0.1:8090/premiya/Эффекты/scroll-burn/
```

Отдельный `http.server` поднимать не нужно. На сайте сервер не нужен — эффект
статический.

Что уже проверено:

- ошибок в консоли и упавших запросов нет;
- шрифты и вёрстка на 1440 / 390 / 320 не ломаются;
- `prefers-reduced-motion` работает;
- пульт, сброс и смена направления проверены;
- в Chromium работает живой SVG-фильтр; в WebKit/Safari 27 он не
  отрисовывается, поэтому для Safari проверена SVG-кромка с CSS-заливкой;
- вне активного прожига (`p = 0` или `p = 1`) `requestAnimationFrame` не
  крутится; пока прожиг в кадре, фильтр пересчитывается, после чего цикл
  останавливается;
- в фоновой вкладке цикл снимается;
- при закрытой вкладке страница и фильтры уничтожаются; отдельных серверных
  процессов у демо нет — его раздаёт общий dev-server проекта.

## 3. Жёсткие ограничения

1. **Не менять контент, шрифты, сетку и другие эффекты сайта.** Задача —
   только прожиг между выбранными секциями.
2. **Не добавлять библиотеки, фреймворки и сборку.** Чистые HTML/CSS/JS.
3. **Не использовать платные шрифты.** Эффект вообще не использует шрифты;
   шрифты демо копировать не нужно.
4. **Не копировать демо-разметку экранов и стили `.screen`, `.lab`,
   демо-шрифты.** На сайт идут только ядро эффекта и разметка `.burn`.
5. **Chrome — живой SVG-фильтр, Safari — SVG-фолбэк.** В WebKit 27
   полноэкранный живой фильтр не отрисовывается, поэтому для Safari нужен
   простой SVG-путь с CSS-заливкой внутри `.burn` (абсолютный, `inset: 0`),
   а не `position: fixed`: иначе слой плавает и на стыке появляется щель.
   Настройки Safari: Smoothing 0.32, Start −10, End −100, Blob Size 310 px,
   Noise X 0.008, Noise Y 0.002, Detail 5, Seed 8 (базовый; каждый блок
   получает `seed + index × 17`). Chrome сохраняет свои defaults.
6. **`data-color` — только литеральный цвет** (`#ECE9E3`, `#080607`).
   Canvas `fillStyle` и SVG `fill` не понимают `var(--paper)`.
7. **Не ставить `.burn` внутрь `.wrap`** или узкого контейнера. Слой должен
   быть прямым потомком полноширинной секции.
8. **Не забывать `position: relative` у секции-хоста.** Иначе абсолютный
   `.burn` прилипнет к другому предку.
9. **Не деплоить без явной команды пользователя.** Порядок — в `DEPLOY.md`.
10. **Не трогать удалённые репозитории и не коммитить без просьбы.**

## 4. Как устроено внутри (чтобы не сломать при переносе)

- `.burn` — абсолютный слой внутри уходящей секции. Он перекрывает её контент,
  но имеет `pointer-events: none`, поэтому клики проходят.
- `.burn__pad` — контейнер с живым SVG-фильтром.
- `.burn__fill` — цветной слой. Растягивается по `scaleY(progress)`.
- К SVG-фильтру применены `feTurbulence` → `feDisplacementMap` → блюр →
  жёсткий порог альфы; фильтр пересчитывается по мере роста заливки.
- Во время скролла SVG-фильтр **участвует** — это и есть оригинальное
  перетекание кромки.
- Прогресс считается по положению `.burn` относительно вьюпорта и
  сглаживается через `requestAnimationFrame`. Цикл останавливается, когда
  сглаживание догнало цель. В фоновой вкладке — пауза.
- Параметры `displacement`, `frequencyX`, `frequencyY`, `octaves`, `seed`,
  `direction`, `start`, `end`, `smoothing` сразу меняют фильтр и прогресс.
- Все прожиги должны быть полноширинными: фильтр рассчитан на ширину секции.

### Параметры по умолчанию (`DEFAULTS` в `burn.js`)

| Параметр | Значение | Смысл |
|---|---|---|
| `direction` | `'up'` | прожиг снизу вверх |
| `start` | `0` | прожиг = 0, когда верх `.burn` на верху вьюпорта |
| `end` | `-100` | прожиг = 1, когда верх `.burn` на 100% выше вьюпорта |
| `smoothing` | `0.12` | инерция; 1 — мгновенно, 0.02 — лениво |
| `displacement` | `220` | размер кляксы, px |
| `frequencyX` | `0.015` | частота шума по X |
| `frequencyY` | `0.02` | частота шума по Y |
| `octaves` | `3` | детализация |
| `seed` | `7` | зерно рисунка |

В оригинальном Framer-компоненте по умолчанию `start: 100`, `end: 0`.
В демо выставлены `0 / -100`, чтобы секция успевала полностью показаться,
а прожиг шёл, пока она уезжает. Для сайта с высокими секциями рекомендую
`0 / -100`; если нужен режим оригинала — поменяйте значения и проверьте.

Для Safari/WebKit в демо отдельный `WEBKIT_DEFAULTS`: `smoothing 0.32`,
`start -10`, `end -100`, `displacement 310`, `frequencyX 0.008`,
`frequencyY 0.002`, `octaves 5`, `seed 8`. Seed — базовый; у каждого блока
свой рисунок (`seed + index × 17`), чтобы кромки не повторялись.

## 6. Ядро CSS

Добавьте в `css/scroll-burn.css` (или в конец `css/style.css`):

```css
/* Scroll Burn: слой внутри уходящей секции */
.burn {
  position: absolute;
  inset: 0;
  z-index: 5;
  overflow: hidden;
  pointer-events: none;
}

/* Для высокой секции: слой прижат к нижним 100svh.
   Для полноэкранной секции этот модификатор не нужен. */
.burn--viewport {
  inset: auto 0 0;
  height: 100svh;
}

.burn__defs {
  position: absolute;
  width: 0;
  height: 0;
  pointer-events: none;
}

.burn__pad {
  position: absolute;
  /* filter, will-change и visibility ставит JS, когда секция подходит
     к экрану; у далёких секций слой не держим. */
}

.burn__fill {
  position: absolute;
  left: 0;
  width: 100%;
  transform: translate3d(0, 0, 0) scaleY(0);
  /* will-change: transform ставится JS на время близости секции. */
}
```

Секция-хост:

```css
.burn-host { position: relative; }
```

`overflow: hidden` секции не обязателен: `.burn` сам обрезает свою полосу.
Не ставьте `overflow: hidden` на секцию, если внутри есть `position: sticky`.

Если у следующей секции видна линия `border-top`, погасите её только на стыке:

```css
.burn-next { border-top-color: transparent; }
```

## 7. Разметка

### Высокая секция сайта (рекомендуемый вариант)

```html
<section class="section burn-host" id="about">
  <div class="wrap">
    ...существующий контент...
  </div>

  <div class="burn burn--viewport"
       data-burn
       data-color="#ECE9E3"
       aria-hidden="true"></div>
</section>
```

`#ECE9E3` — цвет **следующей** секции (`#mission`, `.section--soft`).

### Полноэкранная секция

```html
<section class="screen burn-host" id="...">
  ...контент...
  <div class="burn" data-burn data-color="#080607" aria-hidden="true"></div>
</section>
```

### Следующая секция

Если хотите идеально бесшовный стык:

```html
<section class="section section--soft burn-next" id="mission">
```

Либо задайте `border-top-color` следующей секции равным её фону.

## 8. Подключение

В `<head>` после `css/style.css`:

```html
<link rel="stylesheet" href="css/scroll-burn.css?v=1" />
```

В конце `<body>` после `js/app.js`:

```html
<script src="js/scroll-burn.js?v=1"></script>
```

Скрипт сам находит все `[data-burn]` и инициализируется. Порядок секций в DOM
задаёт индекс прожига (для зеркалирования). Никаких ручных вызовов не нужно.

## 9. Какие секции сайта выбрать

Фон секций:

- `.section` — тёмный, `--ground` `#080607` (фон body);
- `.section--soft` — бумага, `--paper` `#ECE9E3`;
- `.hero` — тёмный;
- `.section--principles` — тёмный (плюс топор — контент, не фон).

Прожиг виден только там, где фон следующей секции отличается от текущей.
Тёмный → тёмный (например, `#dates` → `#awards`) смысла не имеет.

## 10. Порядок переноса (шаги для ИИ)

1. Прочитать `README.md`, `burn.js`, `burn.css`, этот файл.
2. Скопировать `burn.js` в `js/scroll-burn.js`; ничего не переименовывать
   в классах `Burn`/`MaskStore`.
3. Создать `css/scroll-burn.css` с ядром из раздела 6; подключить после
   `style.css`.
4. Подключить `js/scroll-burn.js` в конце `body` (после `app.js`).
5. Выбрать 2–4 перехода из раздела 9.
6. У outgoing-секций добавить класс `burn-host` (`position: relative`).
7. Внутрь каждой outgoing-секции последним child добавить `.burn
   burn--viewport` с `data-burn`, `data-color` следующей секции и
   `aria-hidden="true"`.
8. У следующей секции при необходимости добавить `burn-next` или
   `border-top-color: transparent`, чтобы не было 1px-шва.
9. Убедиться, что `.burn` — прямой потомок секции, а не `.wrap`.
10. Проверить, что фон следующей секции плоский и совпадает с `data-color`.
11. Поменять `DEFAULTS` в `js/scroll-burn.js`, если нужны другие
    `start`/`end`/`smoothing`; для сайта оставить `0 / -100`. Для Safari
    добавить отдельный `WEBKIT_DEFAULTS` с настройками из демо
    (0.32 / −10 / −100 / 310 / 0.008 / 0.002 / 5 / 8) и `seed + index × 17`
    для каждого блока, чтобы Chrome и WebKit не тянули один набор.
12. Пульт на сайт не тащить: разметку `.lab` не копировать. Скрипт без неё
    работает (guard). Для настройки используйте отдельное демо, потом
    перенесите значения в `DEFAULTS`.
13. Поднять версии: `scroll-burn.css?v=1`, `scroll-burn.js?v=1`; если
    правили `style.css` — поднять его `?v=`.
14. Пройти чек-лист из раздела 12.
15. Деплой — только по команде, по `DEPLOY.md`.

## 11. Подводные камни

- **Плоский фон обязателен.** Если у следующей секции градиент, шум, картинка
  или паттерн у верхней кромки — цвет прожига не совпадёт, будет виден шов.
  Либо делайте фон плоским, либо не ставьте прожиг на этот стык.
- **`data-color` — литерал.** `#ECE9E3`, `#080607`, `#F56624`; не
  `var(--paper)`. Canvas и SVG `fill` не резолвят CSS-переменные.
- **`position: relative` у секции.** Иначе `.burn` будет позиционироваться
  относительно другого предка.
- **Полная ширина.** Все `.burn` должны быть в полноширинных секциях:
  `MaskStore` берёт ширину первого прожига. Не ставьте их в колонки/карточки.
- **z-index.** `.burn` — 5; шапка сайта — 50. Не поднимайте прожиг выше шапки.
  Контент секции обычно ниже; топор в `#principles` (`z-index: 1`) тоже будет
  перекрыт — это нормально, он уходит вместе с секцией.
- **Клики.** `pointer-events: none`; прожиг не должен блокировать кнопки.
  Но помните: визуально закрытый контент остаётся кликабельным; не размещайте
  важные CTA только в последних 100vh уходящей секции.
- **Линия `border-top`.** У `.section` есть `border-top: 1px solid var(--rule)`.
  На стыке она может проступить поверх прожига. Гасите её классом `burn-next`
  или цветом фона.
- **Sticky-шапка.** Секции с прожигом не должны получать `overflow: hidden`,
  если внутри есть `position: sticky`; `.burn` обрезает себя сам.
- **Мобильный `100svh`.** Для `.burn--viewport` используйте `100svh`, чтобы
  адресная строка не меняла высоту.
- **Производительность.** В Chrome на каждый прожиг — живой SVG-фильтр,
  в Safari — статичный SVG-путь. Граф фильтра не меняется на кадре; убирайте
  `feFlood`/`feComposite`, если цвет уже есть у заливки. `will-change`
  и `visibility` включайте только у близких секций и готовьте слой до начала
  прожига. В WebKit путь стройте один раз, на скролле двигайте `transform`,
  а не пересобирайте `d`. 2–4 прожига нормально; на слабых машинах
  уменьшайте число прожигов или отключайте эффект.
- **Safari.** В WebKit 27 полноэкранный живой SVG-фильтр не отрисовывается.
  Для Safari нужен SVG-фолбэк с CSS-заливкой (как в демо), Chrome оставляет
  живой фильтр. Путь — абсолютный внутри `.burn`, не `position: fixed`;
  заливка уходит на 2 px ниже низа секции, чтобы на стыке не проступила
  полупрозрачная кромка. Цвет задаётся тем же `rgb()`, что и фон следующей
  секции, — без канваса и его цветового профиля.
- **Динамические секции.** Скрипт инициализируется один раз по DOM. Если
  секции добавляются позже через JS, нужно вызвать инициализацию повторно
  (текущий IIFE не экспортирует API; для SPA это надо адаптировать).
- **Тема.** Если на сайте появится переключение темы, `data-color` нужно
  обновлять вручную или резолвить цвет через `getComputedStyle`.

## 12. Чек-лист приёмки

### Визуал

- [ ] На выбранных переходах появляется органическая кромка, а не ровная линия.
- [ ] Цвет кромки точно совпадает с фоном следующей секции.
- [ ] На стыке нет шва и нет 1px-линии (или линия осознанно оставлена).
- [ ] При скролле вверх прожиг отступает.
- [ ] Контент следующей секции не закрыт прожигом раньше времени.
- [ ] Шапка, меню, аккордеоны и якоря работают поверх/рядом с прожигом.

### Код

- [ ] `document.querySelectorAll('[data-burn]').length` равен числу прожигов.
